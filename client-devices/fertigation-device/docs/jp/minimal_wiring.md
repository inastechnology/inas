# FGT 最小構成配線

## 適用範囲

これは現在のFGT F/Wと初回動作確認で使用するXIAO ESP32-C6直結構成の
PIN契約である。FGT専用基板はまだ存在しない。

`hardware/esp32c6-solar-controller`以下のKiCadデータは将来基板の開発中資料であり、
この配線には使用しない。KiCad基板側に記載された別のPIN配置より、以下の表を
現在の正として扱う。

## GPIO割り当て

| XIAO ESP32-C6 | GPIO | 接続先 |
|---|---:|---|
| D0 / A0 | 0 | バッテリー電圧ADC入力（MOSFET接続禁止） |
| D1 | 1 | 給水用MOSFETスイッチの信号入力 |
| D2 | 2 | A液用MOSFETスイッチの信号入力 |
| D3 | 21 | B液用MOSFETスイッチの信号入力 |
| D4 | 22 | 攪拌用MOSFETスイッチの信号入力 |
| D5 | 23 | 潅水用MOSFETスイッチの信号入力 |
| D6 | 16 | RS485トランシーバのDI |
| D7 | 17 | RS485トランシーバのRO |
| D8 | 19 | RS485トランシーバのDEと`/RE` |
| D9 | 20 | RS485センサー12 V電源スイッチのEN入力 |
| D10 | 18 | 未使用（将来拡張用） |

裏面GPIOは使用しない。

XIAO本体のBOOTボタンは`GPIO9`に接続されている。D0の`GPIO0`とは別であり、
F/Wでは`GPIO9`をAP設定画面の起動・接続設定消去ボタンとして使用する。

## バッテリー電圧監視

`D0/A0/GPIO0`はバッテリー電圧監視専用とし、アクチュエータ出力には使用しない。
バッテリー電圧を等しい200 kohm抵抗で1/2へ分圧し、A0へ入力する。

```text
BAT+ ---- 200 kohm ----+---- XIAO D0 / A0 / GPIO0
                       |
                     200 kohm
                       |
BAT- / GND ------------+
```

- A0へバッテリーを直接接続しない。
- 上下の抵抗値は同じにし、分圧比を1:2とする。
- BAT-、XIAO GND、5 V/12 V電源GNDを共通にする。
- F/Wは`analogReadMilliVolts()`を16回実行して平均し、2倍して
  `battery_voltage_v`として送信する。
- `battery_adc_mv`は分圧後のADC入力電圧、`battery_voltage_ok`はADC初期化・
  読み取り状態を示す。

## アクチュエータ回路

5出力とも同じ低側MOSFET回路を使用する。

```text
XIAO GPIO ---- 100 ohm ---- Gate  N-MOSFET
                              |
                            47 kohm
                              |
GND ------------------------ Source
                              |
負荷マイナス --------------- Drain

+12 V ----------------------- 負荷プラス

                    +V
                     |
        +------------+------------+
        |                         |
      ポンプ                 Flyback diode
        |                 cathode |<| anode
        +-------------------------+
        |
      MOSFET Drain
```

ダイオードはカソードを負荷電源プラス、アノードをMOSFET Drainへ接続する。
現在のポンプはA液・B液用蠕動ポンプを含めてすべて12 Vとする。XIAO用5 V
ロジック電源、12 V電源、MOSFET、RS485トランシーバのGNDは共通にする。

## RS485とセンサー

```text
XIAO D6/GPIO16 ---- DI    RS485トランシーバ
XIAO D7/GPIO17 <--- RO
XIAO D8/GPIO19 ---- DE
XIAO D8/GPIO19 ---- /RE
XIAO 3V3 ---------- VCC
XIAO GND ---------- GND

トランシーバ A ----+---- 土壌センサー A
                   +---- PARセンサー A
トランシーバ B ----+---- 土壌センサー B
                   +---- PARセンサー B
共通GND -----------+---- 両センサー GND
切替12 V ----------+---- 両センサー V+
```

D6/D7を裸のMAX3485または基板上のRS485トランシーバへ接続する場合は、上記の
`D6/TX -> DI`、`D7/RX <- RO`とする。外付けの`RS485 V2.05` MAX3485 moduleを
使用する場合はmodule側から見た`TXD`/`RXD`表記のため、次のようにクロス接続する。

```text
XIAO D6/GPIO16 / TX ----> module RXD
XIAO D7/GPIO17 / RX <---- module TXD
XIAO D8/GPIO19      ----> module EN
XIAO 3V3            ----> module VCC
XIAO GND            ----- module GND
```

D8には47 kohmのGNDプルダウンを付け、起動時を受信モードにする。土壌とPARは
同じバスへ並列接続し、異なるModbusアドレスを設定する。

## センサー電源EN

```text
XIAO D9/GPIO20 -- 100 ohm -- 12 V高側ロードスイッチのEN
                         |
                       47 kohm
                         |
                        GND

12 V入力 ---- 高側ロードスイッチ ---- 土壌・PARセンサー V+
```

GPIO20からセンサーへ直接給電しない。3.3 V EN入力を持つロードスイッチか、
P-MOSFETとNPNトランジスタによる12 V高側スイッチを使用する。

## APモードでの出荷動作確認

リセットまたは電源投入後3秒以内にXIAOのBOOTボタンを押し始め、5秒以上10秒未満
保持して離す。`INAS-FGT-setup`へ接続して`http://192.168.4.1/`を開き、
「FGT 出荷動作確認」を選択する。10秒以上保持すると接続設定の消去になるため、
出荷動作確認だけを行う場合は10秒になる前に離す。

画面から次を確認できる。

- 給水、A液、B液、攪拌、潅水の各MOSFETを指定秒数だけONにする
- RS485センサー用12 V電源をON/OFFする
- センサー電源を自動でONにして対応センサーを検出する
- センサー名、現在のアドレス、土壌値またはPAR値を単位付きで表示する
- 検出したセンサーごとに値取得試験を繰り返す
- センサー名と接続場所・用途を付けて構成を保存する
- 登録済みセンサーを有効化、無効化、編集、削除する
- 検出したセンサーを選び、Modbusアドレスを書き換えて再試験する

ユーザーによる通信速度、Function、レジスタ番号の入力は不要である。自動検出は
ID 1～10、2400/4800/9600 bpsを確認し、次の2機種を識別する。

- 土壌センサー: RS485土壌水分・地温・ECセンサー（3-in-1）
- PAR（日射）センサー: DFRobot SEN0641 PAR

現行FGTの土壌センサープロファイルは先頭3レジスタだけを読み、水分、地温、ECを
表示する。pH、窒素、リン、カリウムには対応しない。PARセンサーはPARを
`µmol/m²/s`で表示する。CRCが正常なModbus応答を取得できた場合を通信成功とし、
土壌水分0～100 %、温度-40～85 ℃、EC 0～20000 µS/cmについてプロトコル上の
範囲確認も行う。これは栽培上の適正値判定ではない。PARは暗所で0になり得るため、
0でも通信応答が正常なら値取得成功とする。

土壌センサーの地温またはECを確認できない応答はPAR候補として表示し、
画面に「機種推定」と明示する。値取得自体の成功と機種識別の確度を混同しない。

自動検出はHTTP要求の中で全アドレスを連続走査せず、セットアップポータルのループで
1アドレスずつ進める。画面は進捗APIから完了数を取得する。このため、全アドレスが
応答タイムアウトになった場合でも、APのHTTP通信タスクを長時間占有しない。
ESP32-C6ではUSBログと独立したUART1をD6/GPIO16・D7/GPIO17へ使用する。ESP-IDF
5.xでUART RXが受信不能になる事例への対策として、UARTを接続する前にD7/RXを
内部プルアップ付き入力として初期化する。通信速度の初期化後に20 ms、各Modbus
要求の間に30 ms待つ。D8/ENはアプリによるGPIO手動切替ではなく、ESP-IDF UART
ドライバの`UART_MODE_RS485_HALF_DUPLEX`でRTSとして制御する。UARTドライバは
送信開始時にENをHIGH、最終ビット送信完了時にLOWへ戻す。APモード中のログには
UART書込長、`en_control=idf_uart_rts`、RXアイドルレベル、送受信バイト列を表示する。
RXアイドルが`LOW`の場合はmodule電源、`module TXD -> D7/RX`、A/Bの
バスバイアスを確認する。

起動時にはUART1内部で8バイトを折り返す自己試験を行い、ログへ
`[RS485 LOOPBACK] mode=internal ... result=PASS`を表示する。この試験がPASSなら
UARTペリフェラル、送信FIFO、受信FIFO、ドライバは動作している。

AP画面の「D6-D7配線試験」は物理ピンまで確認する。センサー12 VをOFFにし、
MAX3485 moduleをD6・D7・D8から外してから、XIAOのD6-D7だけをジャンパ線で
直結して実行する。moduleを接続したままD6-D7を短絡してはならない。
`mode=external_d6_d7 ... result=PASS`ならXIAOのD6/TXとD7/RXまで正常であり、
残る確認対象はMAX3485 module、EN配線、A/B配線、センサー電源とセンサー本体である。

### 1台ずつ登録する手順

1. 登録するセンサー以外をRS485バスから外す。
2. 「センサーを自動検出して試験」を実行し、1台だけ検出され、値取得OKになることを
   確認する。
3. 必要なら、登録前に未登録センサーとしてModbusアドレスを変更する。
4. 「登録するセンサー種別」が実機ラベルと一致することを確認する。自動判定が違う
   場合は、ここで「土壌センサー」または「PAR（日射）センサー」へ訂正する。
   FGTの推奨割り当てではModbusアドレス3をPARセンサーとして自動判定する。
5. 「センサー名」に人が識別できる名前を、「接続場所・用途」に現場で配線を追える
   場所を入力する。
6. 「検出した1台を登録」を押す。選択した種別の測定レジスタを再読取し、通信と
   値域を確認できた場合だけ保存する。
7. 次のセンサーへつなぎ替えて同じ手順を繰り返す。
8. 全センサーを接続し直し、登録一覧のアドレスと実配線が一致することを確認する。

自動識別は、センサーが応答したレジスタ範囲とFGTの推奨アドレス割り当てに基づく。
機種固有IDではないため、実機ラベルを最終確認とする。SEN0641の一部個体は複数の
保持レジスタ読取へ非ゼロ値を返すため、アドレス3のPAR予約判定を追加している。
別の割り当てで使用する場合は、登録前の種別選択で訂正する。

自動検出後の「共有用センサー通信ログ」には、各Modbus取引の通信速度、アドレス、
Function、開始レジスタ、レジスタ数、成功時の応答値、自動識別の判定根拠が表示
される。「通信ログをコピー」で全文をコピーできる。AP内蔵ブラウザでコピーできない
場合は通常のブラウザで画面を開き、ログ本文を長押しして選択・コピーする。
Wi-Fi/MQTTのパスワードは通信ログへ含めない。

最大8台を登録できる。同じ通信速度で同じModbusアドレスを持つ2台は登録できない。
登録一覧では、通常運転で一時的に使用しないセンサーを無効化できる。削除しても
センサー本体に書き込まれたModbusアドレスは変化しない。

登録内容は、機種、センサー名、接続場所、Modbusアドレス、通信速度、Function、
開始レジスタ、レジスタ数、係数である。LittleFSへバージョン、サイズ、CRC付きで
保存し、一時ファイルとバックアップを経由して更新する。APモードと通常運転は同じ
登録内容を読み込む。保存完了の応答は、書き戻したファイルのサイズ、バージョン、
CRCを再読取して確認した後にだけ返す。

登録時にAP接続が切れた場合は、`INAS-FGT-setup`へ再接続して出荷動作確認画面を
開き直し、「障害診断」の「共有用診断データを表示」を開く。ここにはF/Wバージョン、
本体の再起動理由、登録処理が再起動で中断されたか、保存処理の失敗箇所、登録前後の
HTTPタスク最小空きスタックと空きヒープが表示される。Wi-Fi/MQTTのパスワードは
含まれない。診断データを省略せず共有し、`panic`、`task_watchdog`、`brownout`、
`readback_verification_failed`などの値を切り分けに使用する。

一度でもローカル登録を保存した後は、この登録内容を物理RS485構成の正として使用する。
通常運転は有効な登録センサーへ順番にアクセスし、必要に応じて通信速度を切り替える。
Hubから受信するRuntime Configのレシピ、制限、スケジュールは従来どおり使用するが、
従来の固定`soil`/`par`設定は、ローカル登録がまだ存在しない場合だけ互換設定として
使用する。登録をすべて削除した状態も保存され、その場合はRS485センサーを読まない。

MOSFET出力は同時に1つだけONでき、最大30秒で自動OFFする。OFF後は3秒間、
次の出力をONにできない。この保護時間中に別のON要求を送っても拒否される。
また、いずれかのMOSFETがONの間はセンサー電源操作とModbus操作を拒否する。
通信や画面に異常が出た場合も、まず「全出力OFF」を押し、外部の12 V非常停止で
ポンプ電源を遮断する。

同じModbusアドレスのセンサーを複数台接続したままでは、書換え対象を選別できない。
アドレス変更時は対象1台だけをA/B/GND/12 Vへ接続し、変更完了後に次のセンサーへ
つなぎ替え、「センサーを自動検出して試験」を再実行する。CWT-SOILとSEN0641で
確認済みのアドレスレジスタ`0x07D0`はF/Wが自動使用し、画面では入力させない。
新規センサーは「未登録センサー」を選ぶ。登録済みセンサー本体を変更する場合だけ、
一致する登録名を明示的に選択する。書換え後の再読取に成功してから保存済みアドレスを
更新するため、工場出荷時アドレスが既存センサーと同じ新規センサーを、誤って既存の
登録とみなさない。

### APモードからF/Wを更新する

「FGT 出荷動作確認」の「F/Wアップデート」を押すと、ネットワークやMQTTを使わずに
ブラウザからアプリF/Wを更新できる。リリースパッケージを展開し、中にある
`firmware.bin`を選択して「更新を開始」を押す。`.inasfw`、ZIP、工場書込み用の
結合バイナリ、別機種のF/Wは選択しない。

スマホで「ファイルを選択」が反応しない場合、AP接続時に自動表示されたログイン用の
簡易ブラウザを閉じ、`INAS-FGT-setup`へのWi-Fi接続を維持したままSafariまたは
Chromeを通常起動する。`http://192.168.4.1/fgt/firmware-update`を直接開き、
事前にスマホ本体の「ファイル」または「ダウンロード」へ保存した`firmware.bin`を
選択する。ファイル入力の種類制限はモバイルの互換性のため設けず、F/W側で`.bin`
拡張子、ESPアプリイメージ、FGT用マニフェストを検証する。

更新開始時、F/Wはセンサー自動検出を中止し、5つのMOSFET出力とRS485センサー用
12 V電源をすべてOFFにする。更新が終わって再起動するまでは、出荷動作確認画面の
出力、センサー、Modbus設定操作を受け付けない。

アップロードしたファイルについて、ESPアプリイメージの先頭値と、埋め込まれた
INAS F/Wマニフェストのプロジェクト、機器種別、対象ボード、フレームワークがFGT用
であることを確認してから更新を確定する。アプリF/Wは現在動作していないOTA
パーティションへ書き込む。LittleFSには書き込まないため、Wi-Fi/MQTT接続設定と
保存済みRS485センサー構成は維持される。不適合または中断されたアップロードでは
現在の起動パーティションを変更しない。成功時は約2秒後に自動で再起動する。

更新中はUSB電源と12 V電源を切らない。状態LEDの点滅間隔は次のとおり。

- 通常のAPモード: 500 ms
- アップロード・書込み中: 100 ms
- 更新完了・再起動待ち: 50 ms
- 更新失敗: 1000 ms

## 時間設定

単純な潅水や動作確認では`fgt.timed_outputs.enabled=true`にし、各出力を秒数で
設定する。連続運転はON時間と繰り返し1回、分割運転はON時間、OFF時間、
繰り返し回数を設定する。繰り返し0回はその出力を無効にし、保存済みの
ON/OFF時間は動作に使用しない。有効な出力はON時間1〜1800秒、OFF時間
0〜1800秒、繰り返し1〜99回で、複数出力を設定した場合も出力番号順に
1つずつ動く。

例としてA液ポンプだけを2分動かす設定は次のとおり。

```json
{
  "fgt": {
    "enabled": true,
    "timed_outputs": {
      "enabled": true,
      "water_inlet": {"on_sec": 0, "off_sec": 0, "repeat_count": 0},
      "nutrient_a": {"on_sec": 120, "off_sec": 0, "repeat_count": 1},
      "nutrient_b": {"on_sec": 0, "off_sec": 0, "repeat_count": 0},
      "mixer": {"on_sec": 0, "off_sec": 0, "repeat_count": 0},
      "irrigation": {"on_sec": 0, "off_sec": 0, "repeat_count": 0}
    }
  }
}
```

従来の液肥レシピ運転では、物理流量・液面入力を使用せず、Runtime Configの
次の秒数で工程を終了する。
このPIN配置には漏水・非常停止入力もないため、監視下の水だけの試験に限定し、
ポンプ12 V系を直接遮断する外部非常停止を用意する。無人運転や液肥投入用の
安全構成ではない。

- `initial_fill_sec`
- `final_fill_sec`
- `irrigation_sec`
- `rinse_fill_sec`
- `rinse_drain_sec`

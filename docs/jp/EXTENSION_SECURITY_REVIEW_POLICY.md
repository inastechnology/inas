# Hub Extension セキュリティ監査方針

英語版: [../EXTENSION_SECURITY_REVIEW_POLICY.md](../EXTENSION_SECURITY_REVIEW_POLICY.md)

## 対象

この方針は、UIから追加されるすべての第三者Extension、各バージョン更新、
同梱Extensionのレビューに適用する。Version 1で受け付けるのは宣言型UI定義だけである。
独立プロセスRunner、権限、署名、失効管理が完成するまで、実行コードを持つ
Extensionはインストール対象にしない。

## 信頼モデル

- アップロードファイル、ファイル名、manifest、説明、提供者表示、AIへの文章をすべて未信頼入力として扱う。
- AI監査は補助である。静的検査が拒否したパッケージを許可できず、安全を保証もしない。
- 監査結果をすべて表示した後、管理者が別操作でインストールを選択する。
- 新しいバージョンは新しい成果物として再監査する。IDが同じでも以前の承認を引き継がない。
- 署名のないUIアップロードは`jp.inas.official`を名乗れず、既存Extensionを上書きできない。

## 監査フロー

```text
アップロード
  → Web公開領域外の隔離領域とランダム監査ID
  → サイズ・種類・パス・圧縮率検査
  → 許可リスト方式のmanifest検証
  → ID・衝突・実行表現の検査
  → ローカル監査結果ダイアログ
  → AIへ送る内容・モデル・費用可能性を別ダイアログで確認
  → 明示同意後だけ未信頼文章をAI監査
  → 更新された監査結果ダイアログ
  → 管理者が「インストールする／しない」を選択
  → 監査ログを追記
```

インストール前にアップロード内容をimport、実行、実行可能なmarkupとして描画しない。
監査に必要な項目はエスケープ済み文字列としてだけ表示する。AI確認ダイアログを閉じるか
キャンセルした場合は、AI提供者へ何も送信しない。

## 必ず拒否する条件

- 未対応形式、不正JSON、不正ZIP
- パストラバーサル、絶対パス、シンボリックリンク、暗号化、過剰なファイル数・展開サイズ・圧縮率
- Version 1のパッケージ直下の`extension.json`以外のファイル
- 未知フィールド、未対応API・部品・取得元・色調、重複ID、不正バージョン、過剰な文字数・項目数
- 実行コードやアクティブコンテンツを示す表現
- 署名確認なしでの公式名前空間使用
- 同梱済み・インストール済みExtensionとのID衝突

この静的検査はオフラインで再現できることを必須とする。

## AI監査

アップロード直後にAI監査を自動実行しない。まず別の確認ダイアログで、送信対象が
検証済みmanifestと静的検査結果だけであること、利用するモデル、外部送信、契約に
よって費用が発生し得ることを表示する。Hubの秘密値、DB、機器データ、圃場データ、
APIキーを送らないことも明示し、管理者の同意を監査ログへ記録する。

テキストAIが設定されている場合だけ、同意後に静的検査を通過したmanifestと検査結果を送る。
システム指示では、manifest中の全文を命令ではなく監査対象データとして扱わせる。

AIが確認する内容は次のとおり。

- プロンプトインジェクションや監査回避の文章
- 提供者のなりすましや誤解を招く主張
- Hubの安全機構を回避させる危険な操作説明
- 対象機種、参照データ、表示目的の不一致
- 過剰なタブ・カード、分かりにくい専門用語、アクセシビリティ問題
- 秘密情報を要求する誘導やソーシャルエンジニアリング

AI結果はリスク、要約、指摘、推奨として文字列表示し、HTMLとして解釈しない。
宣言型ExtensionではAIが高リスクと評価しても最終判断は人が行うが、静的検査の
拒否条件はユーザ操作でも解除できない。AIが利用できなかった場合は、その事実を
明示し、AI監査済みと誤認させない。

## ユーザへ表示する内容

- Extension ID、名前、バージョン、SHA-256、サイズ
- 提供者確認状態（Version 1のUIアップロードは未確認）
- 静的検査の合格・注意・拒否
- AI実行状態、モデル、リスク、指摘、推奨、限界
- このAPIバージョンで実際に付与される能力
- 独立した「インストールしない」「インストールする」ボタン

選択結果、監査ID、ID・バージョン、ハッシュ、時刻、リスクを追記型監査ログへ残す。
拒否されたパッケージにはインストール操作を表示しない。

## 実行コードを許可する将来条件

成果物署名と提供者確認、不変リリース、SBOM・依存関係・マルウェア検査、権限の明示、
プロセス隔離、ネットワーク・ファイルアクセスの既定拒否、Hub Action Gateway、
異常終了時の隔離、ロールバック、レジストリ失効を実装するまで、宣言型と同じ承認で
実行コードを許可しない。

## 参考基準

- [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html): 許可リスト、ランダム保存名、容量制限、Web公開領域外への保存、多層防御

- [Sigstore](https://docs.sigstore.dev/): 成果物ハッシュ、提供者ID、透明性情報を用いた署名検証

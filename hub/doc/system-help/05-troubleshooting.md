# 困ったときの確認

## アプリ設定を保存できない

Cloudflare経由でアプリ設定を保存するときは、Hub初期設定の公開hostnameと、ブラウザで開いているURLが一致している必要があります。`same-origin request is required` と表示された場合は、ブックマークやアドレス欄がHubの正式なHTTPS公開URLになっているか確認し、ページを再読み込みしてください。現在のHubはブラウザのsame-origin情報を優先するため、Cloudflare Tunnelが内部向けHostへ置き換える構成でも保存できます。外部サイトや別サブドメインからの書き込みは引き続き拒否します。

## 機器が見つからない

最初の画面には全機器を表示しません。対象圃場を選び、「環境・設備」または設置ビューを確認してください。未割り当ての機器は機器管理側で登録・承認状態を確認し、設置エディタで圃場と配置先へ割り当てます。

## 機器へ設定が反映されない

機器詳細の「概要」で通信、設定受信、時刻同期を確認します。「動作設定」で下書きを保存しただけの場合は、機器へ送信する操作も行います。機器がオフラインまたはスリープ中の場合は、次回通信まで反映を待つことがあります。詳しい受信状態は「保守・管理」の「？」と「通信・接続履歴」で確認します。

## 値やグラフが表示されない

その機器が対象の測定に対応しているか、設置ビューで計測対象が割り当てられているか、最終通信が新しいかを確認します。Hub は現在値がない測定項目を画面に生成しません。値はあるが目標帯がない場合は、作物側の目標設定を確認します。

## 保存時に競合が表示された

別の利用者または別タブが先に保存しています。最新版との比較・統合画面で、自分の変更、相手の変更、現在値を確認してから保存し直します。ブラウザを更新する前に、未保存の入力内容を確認してください。

## 予約した潅水が実行されない

Hub は運転異常を状態受信時に検知すると、機器一覧、圃場ビュー、機器詳細へ赤い警告を表示します。赤い機器を開き、「保守・管理」で運転履歴の読み取りエラー、安全確認後の復旧待ち、出力異常、実行しなかった理由を確認してください。Discord 通知が有効なら、異常理由と確認画面へのリンクも直ちに通知します。通知は原因を確認するためのもので、漏水・非常停止・出力異常を無視して遠隔で強制運転するものではありません。

FGTファームウェア0.2.3以降では、ソフトウェア更新や一時的な遅延で取り逃した予約が6時間以内で、正常な保存履歴を確認できる場合に限り、最新の1件を1回だけ追いつき実行します。6時間を超えた予約、複数の古い予約、初回起動・履歴消去後、安全停止中の処理は自動実行しません。0.2.2以前のFGTにはこの追いつき機能がないため、ファームウェア欄を確認してください。

## 潅水後の水分通知が届かない

「アプリ設定」→「通知」で、Discord Webhook、「すべてのDiscord通知」、「潅水後の水分チェック」の状態を確認します。次に設定ウィザードで、対象の潅水機と判定センサーがどちらも「利用中」で、チェック自体がONか確認します。

潅水機が実行済みの状態をまだ送っていない場合や、選択センサーが潅水後の測定値をまだ送っていない場合は判定されません。省電力センサーでは次回通信を待ちます。下限以上なら正常扱いのため通知しません。詳しい判定タイミングは[潅水後の土壌水分チェック](07-post-watering-moisture-alerts.md)を参照してください。

## Cloudflare の画面へ入れない

Cloudflare Access で許可されたメールアドレスか確認します。Access 認証を通過しても Hub 内の利用者登録がなければアクセスできません。管理者にメールアドレスと必要な権限を確認してもらってください。

## 栽培方法を質問したい

施肥、防除、水やり、病害虫、収穫などの判断は、対象作物の年間カレンダーにある「この作物について質問」を使用します。システムヘルプは Hub の画面と操作方法を回答するもので、個別の農作業判断は行いません。

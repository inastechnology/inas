# 土壌水分の未到達通知への仕様変更 実装計画

## 目的

潅水イベント直後の1測定値を判定する通知を、選択した土壌水分センサーが直近N日間に設定値へ到達していないことを知らせる監視へ変更する。Nは1〜14日で設定でき、夏冬の潅水間隔、手動潅水、降雨を区別せず、根域の水分が一定期間回復していないことを圃場単位で確認できるようにする。

## 境界

- Hub application の監視サービスが、保存済み測定値とルールからローリング期間を評価する。
- Runtime Config の潅水開始しきい値、ファームウェア、潅水機の実行イベントは変更しない。
- ルールは土壌水分センサー単位とし、閾値、監視日数、有効状態を runtime setting に保存する。
- 監視期間内に閾値以上の測定が1回でもあれば到達とみなす。
- 測定履歴が監視期間を十分に覆わない場合は通知せず、判定準備中として表示する。
- Discord送信は既存の通知サービスを利用し、同じ未到達状態では24時間に1回までとする。

## 既存設定の移行

- 旧ルールの `sensor_device_id` と `minimum_percent` と有効状態を保持する。
- 旧ルールの潅水機IDは新しい判定に使わず、監視期間を既定3日としてセンサー単位のルールへ変換する。
- 同じセンサーを参照する旧ルールが複数ある場合は1件へ統合する。
- 旧ルールの潅水待ち状態は新仕様では意味を持たないため破棄する。

## 実装手順

1. ルール検証・移行・保存をセンサー単位へ変更し、1〜14日の履歴を評価するサービスを実装する。
2. MQTT測定受信時と30分ごとの定期タスクから評価し、到達・未到達・データ不足、24時間再通知を管理する。
3. Discordカードを乾燥継続の文面と期間・最新値・最終到達時刻へ変更する。
4. 「環境・設備」のカードをセンサー単位へ変更し、設定ウィザードでセンサー、監視日数、閾値を編集・削除できるようにする。
5. グラフの表示期間を設定したN日に追従させる。
6. user-facing system help、単体テスト、画面テスト、ブラウザテストを更新する。
7. 全検証後にコミット・pushし、運用環境へ反映してhealth/readinessを確認する。

## 完了条件

- 直近1〜14日の範囲で閾値以上が1回もないときだけ通知する。
- 到達中、履歴不足、センサー停止中は水分未到達通知を送らない。
- 未到達が継続した場合は24時間ごとに再通知し、到達後は通知状態を解除する。
- 既存の運用ルールが選択センサー・閾値を失わず3日ルールへ移行する。
- 圃場カードとウィザードがセンサー単位の条件とN日グラフを表示する。
- 管理者が条件を追加・編集・停止・削除でき、operatorは閲覧のみとなる。

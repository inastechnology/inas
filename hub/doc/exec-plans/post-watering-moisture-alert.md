# 潅水後土壌水分アラート実装計画

## 目的

潅水が実行された後、利用者が選んだ土壌水分センサーの次の有効値を確認し、設定した最低水分率に届かなければ Discord へ一度だけ通知する。潅水機ごとにセンサーを選べる設定ウィザードを用意し、アプリ設定と潅水機詳細の両方から到達できるようにする。

## 境界

- Hub application のサービスが、潅水 status と正規化可能な土壌水分 status を関連付けて判定する。
- Runtime Config の潅水開始しきい値とは分離し、ファームウェア設定や GPIO 動作は変更しない。
- 設定は Hub の runtime setting に保存し、監視中の潅水イベントだけをローカル状態ファイルへ保存する。
- Discord Webhook 送信は既存の通知サービスを利用する。

## 実装手順

1. 潅水機別ルールの検証、保存、潅水イベント追跡、土壌水分判定を行うサービスを追加する。
2. device status 保存後にサービスを呼び、WRS の明示的な潅水後測定値、または選択センサーから次に届く有効値を判定する。
3. Discord の潅水後水分不足カードを追加する。
4. センサー選択、最低水分率、確認の順に進む設定ウィザードを追加する。
5. 通知設定と潅水機詳細へウィザード導線を追加する。
6. farmer-facing system help と単体・画面テストを追加し、Hub テストと lint を実行する。

## 完了条件

- 同じ潅水イベントでは通知が重複しない。
- 次の潅水イベントでは再び判定できる。
- 複数の候補から判定センサーを選択し、再表示後も設定が保持される。
- 下限以上では通知せず、下限未満だけ通知する。
- 管理者以外はウィザードを開けない。
- 現在利用できる範囲と未対応範囲がシステムヘルプに明記される。

## 実装上の判断

- 潅水後の設定値は「この値を下回れば通知する最低水分率」とした。乾燥時に潅水を開始する Runtime Config の `moisture_threshold` とは別設定である。
- 判定対象は WTR、WRS、FGT の実行済み status とし、選択センサーは SOI、ENV、WTR、WRS、FGT の土壌水分値を利用する。
- 同じ status に明示的な `soil_moisture_after_watering` があればそれを優先し、それ以外は選択センサーから潅水後に届いた最初の有効値を使う。
- ウィザードへの主導線は「アプリ設定 → 通知」、文脈導線は実機の潅水機詳細に置いた。

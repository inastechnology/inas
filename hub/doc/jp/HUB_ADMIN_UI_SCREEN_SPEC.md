# Hub Admin UI 画面仕様

作成日: 2026-07-14

ワイヤーフレーム:

- [assets/hub-admin-ui-wireframes.drawio](assets/hub-admin-ui-wireframes.drawio)

## 1. 目的

水やり機管理 UI は、API や raw JSON を直接操作する画面ではなく、圃場での設置場所、畝/点滴ライン、土壌水分、灌水状態を直感的に確認し、必要な操作へ迷わず入れる画面にする。

運用者が最初に知りたいことは次である。

- どの圃場/ハウス/畝に問題があるか。
- 選択中デバイスがどこに設置され、どの畝・鉢・水耕ベッド等へ潅水するか。
- 今の土壌水分、灌水状態、次回起床、最終通信は正常か。
- 設定、履歴、保守操作のどこへ進めばよいか。

## 2. ページ階層

| 階層 | URL | 役割 | 主な導線 |
|---|---|---|---|
| TOP | `/` | 圃場を検索して選択する。デバイスを直接列挙しない | 圃場詳細、圃場追加 |
| 圃場一覧 | `/fields` | 圃場の所在地、設置環境、配置・定植状況を検索・比較する | 圃場追加、圃場詳細 |
| 圃場詳細 | `/fields/<field_id>` | 選択した圃場の現在状態、次の判断、環境・設備、定植、記録を確認する | 設置編集、作物編集、作業記録、場所設定 |
| 設置エディタ | `/fields/<field_id>/layout` | 圃場、ハウス、畝、設備を配置し、場所に定植情報と栽培作業を結び付ける | 配置パレット、Canvas、定植、栽培カレンダー |
| 年間カレンダー | `/fields/<field_id>/calendar` | 作物ごとの年間計画、栽培基準、実施記録を期間指定して確認する | 作物切替、期間選択、作業編集・記録、AI再生成 |
| 個人設定 | `/preferences` | ログイン中の利用者だけに適用する表示・栽培助言設定を変更する | タイムゾーン、日付形式、栽培アドバイス習熟度 |
| アプリ設定 | `/settings` | 管理者がHub全体のAI・Instagram・システム設定を検索して変更・確認する | AI、Instagram、接続設定状態 |
| デバイス保守（現行） | `/mqtt-devices`、`/mqtt-devices/<device_id>` | URLを知る管理者向けの既存保守画面。TOPの主導線には置かない | 状態、設定、履歴、保守 |
| API | `/local/api/...` | 機械向け API | 画面上部の主導線には置かない。必要時は保守タブから確認する |

検索可能な単一選択は、選択ボックスを開いたメニュー内に検索入力を表示する共通コンボボックスを使う。実施方法、栽培対象、デバイス・機能、潅水元、記録対象、カメラ、F/W、画像、都道府県などが対象となる。検索欄と選択ボックスを別々に並べない。状態、優先度、設置環境など少数固定値は通常のドロップダウンを使う。検索方式と選択保持の詳細は [HUB_UI_STATE_ACTION_POLICY.md](HUB_UI_STATE_ACTION_POLICY.md) に従う。

主要操作ボタンは、必須入力、保存前状態、権限、通信中などの理由で実行できない場合だけ無効化する。無効な理由が自明でない場合は、ボタン付近に利用者が解消できる具体的な理由を表示し、`aria-describedby` とツールチップにも同じ理由を設定する。特に外部API、設備制御、削除などコストまたは影響のある操作は、画面上の無効化だけに依存せずサーバ側でも前提条件を検証する。

## 3. TOP 画面

TOP はリンク集や全デバイスダッシュボードではなく、利用者が作業対象の圃場を選ぶ入口とする。利用者は圃場を選択してから、その圃場に属するハウス、畝、鉢、定植、センサー、潅水設備へ進む。

表示内容:

- ヘッダーは `INA Device Hub`、`圃場を選択`、`個人設定`、`圃場を追加`を表示する。管理者には `アプリ設定` も表示する。
- 圃場名、市区町村、地区の全文検索を置く。
- 都道府県と設置環境のフィルタを置く。
- 圃場カードには所在地、設置環境、定植、配置、作業記録の圃場単位サマリを表示する。
- 1ページ18件とし、サーバ側ページングを行う。検索条件はページ移動後も維持する。
- TOPではデバイス名、device ID、水やり機一覧、カメラ一覧、デバイス総数を取得・表示しない。
- 圃場が0件の場合も追加ボタンと検索領域を維持する。

## 4. デバイス画面の位置付け

全デバイス一覧は通常の営農導線に含めない。デバイスは圃場詳細または設置エディタから、設置先の文脈を保ったまま確認する。

将来、保守担当者向けのデバイス検索画面を追加する場合は、device ID、シリアル、種別、状態で検索し、結果に所属圃場と設置階層を必ず表示する。無条件で全デバイスを初期表示してはならない。現行の `/mqtt-devices` は既存保守機能の互換URLとして残すが、TOPにはリンクしない。

## 5. 圃場画面

### 5.1 圃場一覧

- ヘッダー右側に `＋ 圃場を追加` を表示する。
- 追加ボタンを押すとモーダルを開く。追加フォームを一覧へ常設しない。
- モーダルで扱う項目は、圃場名、都道府県、市区町村、町名・地区、設置環境だけとする。
- 設置環境は `屋外（露地）`、`ハウス・温室内`、`屋内`、`半屋外`、`その他`から選択する。
- 作物、品種、栽培ステージ、栽培方式、制御方針、デバイス、カメラ、ハウスや畝の配置は追加モーダルで設定しない。
- 圃場カードには所在地、設置環境、配置数、定植数、接続デバイス数を表示する。作物は圃場属性ではなく、定植情報から集約して表示する。

### 5.2 圃場詳細

- ヘッダー直下に `概要`、`環境・設備`、`栽培`、`記録`、`設定` のタブを置き、初期タブを `概要` とする。
- ヘッダーには圃場名、所在地、設置環境だけを表示する。圃場属性として作物や生育段階を表示しない。
- `概要` の最上段は `取得中の環境値` と `作業TODO` の 2 領域とする。現在状態と人間が次に行う作業を初期表示範囲で確認できることを優先する。`作業TODO` は栽培カレンダーの期限候補を先に、センサー・現在値からの即時判断を続けて表示する。
- 土壌水分、土壌 EC、土壌 pH、湿度、PAR は、実際に取得できた指標だけを表示する。未取得指標のカード、`値取得失敗`、`未取得` の件数は表示しない。
- 環境値カード全体を押下可能にし、該当定植の目標値編集へ直接遷移する。URL に `placement`、`planting`、`target_metric` を保持し、設置エディタを開くだけでなく該当指標の編集行へスクロール・フォーカスする。
- 取得値には現在値マーカーを表示し、対応する定植の目標レンジがある場合だけ同じグラフに目標帯を重ねる。
- センサー配置の `target_placement_ids` が定植場所を指す場合は、その定植の目標値を使用する。対象がなく定植が 1 件だけの場合は、その定植を圃場代表として扱う。
- 複数センサーが同じ指標を送る場合は、取得日時が最も新しい値を使用し、デバイス ID、設置空間、取得日時を併記する。
- `概要` には設置ビューのプレビュー画像を表示する。独立した `設置ビュー` ボタンは置かず、画像右上の鉛筆アイコンから編集画面へ遷移する。
- `概要` には `圃場構成` を閉じたアコーディオンで表示し、必要なときだけ `圃場 → 空間 → 培地/設備 → デバイス機能` の包含関係をツリーで確認できるようにする。
- デバイスの潅水対象・計測対象は包含ツリーの親子にはせず、`対象: 畝A、鉢B` の関連として表示する。複数対象を持つデバイスをツリー上で重複させない。
- 畝、鉢、植木、水耕ベッドは既定で `手動潅水` とし、設置エディタで配置済み潅水機を選択できる。潅水機から培地への接続線と培地側の潅水元バッジを表示する。露地エリアは空間であり、培地には含めない。
- `環境・設備` は最初に圃場全体へ集約した土壌水分と潅水の時系列グラフを表示し、その下に `圃場屋外 → ハウス → その他の子空間` の物理スコープ別で設置機器と直近値を表示する。デバイス起点のタブは作らない。
- `栽培` には、鉢、畝、水耕ベッド、植木に紐づく定植を作物単位で表示する。作物名、品種、作物区分、果樹の樹齢、定植日、株数、栽培方式を編集でき、対象作物の年間カレンダーへ移動できる。
- `栽培` の作物ごとに、定植、実施作業、対象培地の潅水・センサー計測を新しい順に最大10件の stepper で表示する。全圃場の履歴は `記録`、作物個別の経過は `栽培` と役割を分ける。
- `記録` の先頭は月間カレンダーとし、定植、作業実績、観察、判断記録、デバイス自動取得件数を日付へ配置する。記録フォームと時系列一覧はカレンダーの後に置く。手入力フォームは必要な記録項目だけをローカル検索・追加する方式とし、デバイス0台でも利用できる。記録一覧は初期20件だけを表示し、キーワード、記録種別、期間を `/local/api/fields/<field_id>/records` へ渡して20件単位で追加取得する。詳細は [HUB_DEVICE_FREE_FIELD_RECORDING_SPEC.md](HUB_DEVICE_FREE_FIELD_RECORDING_SPEC.md) を参照する。
- `設定` で編集できるのは圃場名、都道府県、市区町村、町名・地区、設置環境だけとする。
- 区画、畝、測点を圃場設定として管理しない。畝などの実体は設置ビューの配置物として管理する。
- 潅水、液肥、噴霧の制御先と制御条件はデバイスに属する。圃場設定には保存しない。
- デバイスの設置先、潅水対象、計測対象は設置エディタで設定する。
- ヘッダーのアプリ設定導線から、Hub全体の一般設定、栽培計画用テキストモデル、画像解析モデル、接続確認、上級者向け栽培計画プロンプトフォーマットへ移動できる。AI設定を圃場設定の一部として表示しない。
- 個人設定とアプリ設定を分離する。個人設定は全ユーザー、アプリ設定は管理者だけが利用できる。同時編集の409は入力を消す一般エラーにせず、最新版との比較・統合画面を表示する。
- 個人設定の栽培アドバイスは `初心者`、`標準`、`プロ` から選ぶ。初回計画と再生成の固定フォーマットは共通とし、説明量と専門性だけを切り替える。

状態判定は次の規則とする。

| 条件 | 表示状態 | 総合判定への扱い |
|---|---|---|
| 現在値が下限以上かつ上限以下 | 目標内 | 正常 |
| 現在値が下限未満 | 下限未満 | 確認が必要 |
| 現在値が上限超過 | 上限超過 | 確認が必要 |
| 現在値はあるが目標がない | 目標未設定 | 判定対象外 |

現在値がない指標は判定表へ載せず、画面にも項目を生成しない。

ワイヤーフレームは [assets/hub-admin-ui-wireframes.drawio](assets/hub-admin-ui-wireframes.drawio) の `圃場詳細` ページに定義する。

### 5.3 圃場 TODO

`作業TODO` は、システムが人間の作業を代替するのではなく、「今、どこで、何を、なぜ行うべきか」を提示し、人間が実施、見送り、延期を判断する入口とする。作物名、時期状態、作業を一文にし、`ライチにそろそろ追肥の確認が必要です` のように表示する。

カレンダー由来の TODO はカード全体を押下可能とする。遷移 URL に定植 ID と作業 ID を含め、年間カレンダーへ移動した直後に該当作業の詳細モーダルを開く。単にカンバンを表示して利用者に作業を探し直させない。センサー、設備保守など別の発生源も、対象を特定できる場合は該当設定、計測、診断画面を直接開く。

TODO へ統合する候補の発生源:

- センサー現在値と作物目標の差分。
- 定植日、生育段階、植物管理カレンダーから導かれる追肥、整枝、受粉、収穫などの作業。
- 画像観察、病害虫情報、気象予報から導かれる確認、防除、保護作業。
- デバイス無応答、センサー校正、液切れ、タンク残量などの設備保守。
- 清掃、巡回、定期点検などの繰り返し作業。
- 利用者が登録した任意作業。

各 TODO は最低限、`対象圃場・場所・作物`、`作業名`、`優先度`、`実施候補期間`、`理由`、`判断根拠`、`発生源`、`状態`、`実施記録`を持つ。優先度は植物管理カレンダーと共通の `必須`、`やった方がよい`、`おすすめ`、`好みで` を使用し、時期状態の `期限超過`、`今やる`、`まもなく` とは分離する。

状態は `提案中`、`やる`、`進行中`、`完了`、`延期`、`見送り`を区別する。完了時は利用者が実施日を選び、圃場イベントと作業実績へ同時に記録する。同一原因から重複候補が発生した場合は、対象場所、作業種別、候補期間を使って統合し、根拠だけを追加する。

## 6. 既存デバイス詳細画面

詳細画面は選択中デバイスに集中する。ほかの圃場やほかのデバイスのメニューは表示しない。

表示順:

1. ヘッダー
   - `一覧へ戻る`
   - 選択中デバイス名、設置パス、状態。設置パスから設置エディタの該当配置へ移動できる。
   - API リンクは出さない。
2. 運用判断サマリ
   - WTR/WRS は `次の潅水`、`土壌水分しきい値`、`現在の土壌水分`、`現在の潅水状態` を最初に表示する。次回起動やF/Wより上位に置く。
   - ENV/SOI/PAR は気温、湿度、土壌水分、地温、EC、pH、PAR から機器種別に合う値を表示する。
   - 最終通信、現在F/W、F/W更新状態は概要内の保守情報へ分離する。
3. 設置場所・関連先
   - 機器詳細に独自の設置図を持たない。圃場の `FieldLayoutRepository` を唯一の正本とする。
   - `binding.device_id` から所属圃場、空間、配置物を解決し、`圃場 / ハウス / 配置物` の設置パスを表示する。
   - `binding.target_placement_ids` からWTR/WRSの潅水対象、センサーの計測対象を表示する。
   - 設置パスと対象培地は設置エディタの該当配置へ、圃場名は圃場詳細へ遷移する。
   - 旧 `location` はAPI後方互換のため保存値だけを残す。GUIでは編集・表示せず、レイアウト割当の判定にも使用しない。
4. タブメニュー
   - `概要`: 設置場所・関連先、WTR/WRSの予約、通信・F/W状態。
   - `計測・稼働`: 機器種別に応じた潅水、気温、湿度、土壌水分、地温、EC、pH、PARの時系列グラフと稼働履歴。
   - `動作設定`: 表示名、設置場所、runtime config、MOSFET SW、予約、センサー校正。
   - `F/W更新`: 現在F/W、更新目標、OTA状態・履歴、firmware artifact登録。
   - `履歴・診断`: 承認/停止/廃止、runtime config JSON、raw status/OTA/MQTT履歴。

タブはボタンで切り替え、初期表示では `概要` を開く。`?tab=monitoring|settings|firmware|diagnostics` で目的タブを直接開ける。旧キー `irrigation|config|maintenance` は互換エイリアスとして扱う。タブパネルは HTML 上に残して既存 JS と form id を維持する。

圃場の環境・設備表示と機器詳細の各グラフでは、機器名の横に歯車アイコンを置く。歯車は `/mqtt-devices/<device_id>?tab=settings` に遷移し、対象機器の `動作設定` を直接開く。F/W更新は設定や診断の中へ埋めず、`F/W更新` タブだけで完結させる。

## 7. 操作原則

- 上部ナビはページ遷移だけに使う。API、イベント API、ファームウェア API など機械向けリンクは主導線から外す。
- 詳細画面の機能はタブで 1 段にまとめる。スクロールしないと機能が見つからない状態を避ける。
- 初心者向けの主表示は日本語業務語にする。`channel_mask` は詳細/設定内に残すが、主表示では `mosfet_switches.name` を優先する。
- raw JSON は `履歴・診断` タブ内に閉じる。
- 既存 API と form id は維持する。

設置エディタの詳細は [HUB_INSTALLATION_LAYOUT_SPEC.md](HUB_INSTALLATION_LAYOUT_SPEC.md) を参照する。ワイヤーフレームは draw.io の `設置エディタ` ページに定義する。

植物管理カレンダーの優先度、LLM 生成、修正差分、作業記録は [HUB_PLANT_MANAGEMENT_CALENDAR_SPEC.md](HUB_PLANT_MANAGEMENT_CALENDAR_SPEC.md) を参照する。

## 8. 実装チェック

- TOP ページは圃場の検索・選択画面として表示される。
- TOP ページに水やり機、カメラ、レガシーセンサー、`/mqtt-devices`への導線が表示されない。
- TOPの圃場一覧は18件単位でページングされ、名称・所在地検索と地域・環境フィルタが使える。
- 圃場一覧の追加フォームはモーダルで開き、作物・栽培条件・デバイス項目を含まない。
- 圃場追加時に名前、都道府県、市区町村、設置環境を保存できる。
- 圃場詳細に `概要`、`環境・設備`、`栽培`、`記録`、`設定` のタブがあり、初期表示は `概要` である。
- 圃場詳細の最初に、取得できた現在値と、カレンダー・センサー判断を統合した `作業TODO` が表示される。
- 未取得のセンサー指標は HTML に生成されない。
- 目標レンジは現在値マーカーと目標帯を持つグラフで表示される。
- 下限未満と上限超過は `確認が必要` として表示される。
- 圃場詳細に設置ビューのプレビュー画像があり、右上の鉛筆アイコンから編集画面へ移動できる。
- 圃場詳細に閉じた状態の設置ツリーがあり、展開すると空間、培地、設備、デバイス機能の階層と潅水・計測対象を区別して表示する。
- 設置ツリーと設置プレビューの培地・空間・設備から設置エディタの該当配置へ、デバイスから機器詳細へ、デバイス機能から動作設定へ移動できる。
- `環境・設備` に圃場全体の時系列グラフと、物理スコープ別の設置機器・直近値が表示される。
- 記録タブの先頭が月間カレンダーである。
- デバイス0台でも、潅水時間やECを検索して同じ記録へ追加・保存できる。
- 追加した記録項目を入力前に削除でき、`過去に選択` から再追加できる。
- 同日のデバイス値はデバイス名、値、単位、取得時刻を伴って複数件表示される。
- 圃場設定に作物、栽培条件、区画、測点、目標、制御、デバイスの入力欄がない。
- 詳細ページにほかの圃場カードが表示されない。
- 圃場詳細に `tablist` と 5 つのタブが表示される。
- 機器詳細に `概要`、`計測・稼働`、`動作設定`、`F/W更新`、`履歴・診断` の5タブが表示される。
- 機器詳細は圃場設置ビューの割当から実際の設置パスと潅水・計測対象を表示し、それぞれの圃場・配置へ移動できる。機器メタデータの場所が空でも、圃場または配置へ割当済みなら `未設置` と表示しない。
- WTR/WRSの先頭に次の潅水時刻、土壌水分しきい値、現在値、潅水状態が表示され、次回起動やF/W情報より先に認識できる。
- 潅水・環境センサーのグラフ見出しに対象機器の設定アイコンがあり、`動作設定` タブを直接開ける。
- ENV機器では気温・湿度・PAR、SOI/WRS機器では取得可能な土壌水分・地温・EC・pH・PARのグラフが表示される。
- F/W更新対象、OTA履歴、firmware.bin登録は `F/W更新` タブ内にあり、raw履歴とは分離される。
- 主要フォーム ID は維持する。
  - `runtime-config-form`
  - `metadata-form`
  - `runtime-config-json`
  - `firmware-target-form`
  - `firmware-upload-form`
- デモ一覧/詳細も同じ画面構造で表示される。
- 圃場詳細から設置エディタへ移動できる。
- 設置エディタで D&D、追加、移動、拡縮、編集、削除、保存ができる。
- 設置エディタの配置パレットを同義語・表記揺れのキーワードで検索できる。
- 配置パレットに日陰エリア、植物育成ライト、噴霧器、送風機、空調がある。ホース・配管は施工資料で扱い、Hubの新規配置対象にはしない。
- センサーの計測対象にハウス、露地エリア、日陰エリアを指定でき、空間をまたぐ関連も接続線または画面外端点で確認できる。
- 設置エディタの Canvas 右上に北の向きが常時表示され、空間設定から角度を変更できる。
- ハウスなどの子空間へ移動し、階層ごとに配置できる。
- 保存済みの鉢や畝に作物を定植し、作物名が Canvas とプロパティへ表示される。
- 定植時に作物区分と果樹の樹齢を入力でき、培地に適合する栽培方式だけを選択できる。地域は圃場所在地から取得する。
- 定植時の用土・培地と日当たりは選択式であり、必須項目が揃うまでAI計画生成ボタンを無効化して不足理由を表示する。登録時はサーバへ生成タスクを登録し、目標レンジと12か月計画をAIまたは標準案で非同期生成する。
- 生成タスクが `queued` または `running` の間はボタンを `AI計画を作成中...` に変え、画面を離れても処理が続くことを示す。画面は処理中だけサーバ状態を定期取得し、ページ遷移後も状態を復元する。他の配置編集やページ移動を禁止しない。
- 生成成功時はカレンダーを自動表示し、失敗時はエラーと再実行操作を表示する。同一定植への生成要求は同時に1件だけ許可する。
- 圃場詳細の栽培タブで作物情報を編集でき、設置ビューから対象作物の編集位置へ移動できる。
- 定植直後の栽培カレンダーは全画面モーダルで開く。通常閲覧は設置ビューとは独立した年間カレンダーページとする。
- 栽培カレンダーに期間選択可能なガント、生成条件編集、再生成、作業の手動追加・編集・削除がある。既定は今月から12か月で、過去の開始月と6・12・24か月を選択できる。
- 栽培カレンダーで、初回生成した潅水、施肥、EC、pHの基準と、反復間隔・実施日起点を確認できる。
- 栽培カレンダーで優先度、時期、理由、タグを確認し、利用者が編集できる。
- 栽培カレンダーの管理作業は `未完了`、`作業中`、`完了` の3列カンバンで常時比較する。各列に件数と見積人時、各カードに期間、優先度、作業種別、必要人数、見積時間を表示する。未完了は期限超過、今やる、まもなく、将来の順、同じ時期では優先度順、完了は実施日の新しい順とする。
- カンバン上部に作業検索を置き、作業名、作業種別、理由、手順、時期、タグ、対象、方法・資材をAPIで検索して全列を同時に絞り込む。50件単位でページングし、表示件数と総件数、一致しない場合の空状態を表示する。
- カードを `未完了`、`作業中`、`完了` 列へ D&D できる。未完了と作業中の往復は即時更新し、完了列へのドロップは実績入力モーダルを開く。実績保存前に完了扱いにしない。完了済みカードは移動不可とし、詳細モーダルのボタンでも同じ遷移を行えるようにする。
- カンバンカードはサマリだけを表示し、押下すると作業詳細モーダルを開く。具体的な理由、手順、方法候補、編集、着手、未完了への差し戻し、完了記録は詳細モーダルで行う。
- 未完了作業では実績記録を表示せず、`作業を開始` だけを主操作とする。作業中だけが実績を記録でき、完了は閲覧専用とする。状態別操作の共通原則は `HUB_UI_STATE_ACTION_POLICY.md` に従う。
- 利用者が実施日を選択して作業記録を保存できる。
- 選択中の定植条件とカレンダーを前提に質問できる。

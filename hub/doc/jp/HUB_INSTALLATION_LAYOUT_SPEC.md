# Hub 設置ビュー仕様

作成日: 2026-07-14

ワイヤーフレーム:

- [assets/hub-admin-ui-wireframes.drawio](assets/hub-admin-ui-wireframes.drawio) の `設置エディタ` ページ

## 1. 目的

圃場、ハウス、露地、畝、水耕設備、植木鉢、潅水機、センサーなどの設置関係を、縦横のマスで定義した 2D グリッド上に配置する。

設置ビューは見た目だけの図ではなく、次の運用情報を結び付ける基盤とする。

- 圃場内の空間階層。
- 栽培設備と栽培単位の位置、幅、高さ。
- WTR/WRS、MOSFET SW、センサーなどの設置先。
- 鉢、畝、植木などへ登録した定植情報と栽培カレンダー。
- 将来のデバイス状態、土壌水分、潅水状態の空間表示。

## 2. 画面

| 項目 | 内容 |
|---|---|
| URL | `/fields/<field_id>/layout` |
| 左 | 検索欄と配置パレット。空間、培地、設備のプリセット |
| 中央 | Konva.js によるグリッド Canvas |
| 右 | 選択した配置物、定植情報、または現在の空間のプロパティ |
| 上部 | 圃場へ戻る、階層パンくず、栽培カレンダー、Undo/Redo、Zoom、保存状態、保存 |
| 右ドロワー | 作物別の管理作業、優先度、時期、作業記録、質問 |

狭い画面では、配置パレット、Canvas、プロパティを縦方向へ並べる。配置パレットは横スクロールにする。

Canvas の右上には常に方位マークを表示する。方位マークはパン、ズームの対象に含めず、現在の空間で設定された北の向きを示す。

## 4. 操作

- パレットを Canvas へドラッグして追加する。
- パレットをクリックまたはタップした場合は、現在の空間中央へ追加する。
- 配置物をドラッグするとマス単位で移動する。
- 選択枠の 8 方向ハンドルでマス単位に拡大、縮小する。
- 配置パレットはラベルと検索キーワードを NFKC 正規化して検索する。各プリセットに同義語、表記揺れ、一般名を持たせ、例えば `温室` でハウス、`水やり` で潅水機へ一致させる。この検索契約は記録項目などの選択UIにも適用する。
- 右プロパティで名前、X、Y、幅、高さ、デバイス、使用する系統・計測機能、潅水・計測対象、メモを編集する。デバイス選択ラベルは対象に応じて `紐づける潅水デバイス`、`紐づけるセンサーデバイス`、`紐づける設備デバイス` とする。WRSのMOSFET出力は `使用する潅水系統`、センサーは `使用する計測機能` と表示し、抽象的な `デバイス内機能` という文言は使用しない。
- 畝、植木、植木鉢、水耕ベッドの潅水方法は、関連がない状態を `手動潅水` として扱う。培地を選択すると、配置・デバイス紐付け済みの潅水機へ切り替えられる。露地エリアは空間であり、定植対象の培地として扱わない。
- 潅水機を選択した場合は `接続する培地` から複数の培地を選択できる。培地側から潅水機を選択した場合も同じ `target_placement_ids` を更新する。
- 潅水・計測対象の一覧には `すべて選択` と `すべて解除` を表示する。個別チェックと一括操作は同じ `target_placement_ids` を更新する。
- 同じ空間にある潅水機と培地は、潅水機から培地へ向かう青い接続線で表示する。潅水機に紐づく培地は青い枠と潅水元バッジを表示する。
- センサーは培地に加えてハウス、露地エリア、日陰エリアを計測対象にできる。同一空間は対象へ直接線を描き、親子空間をまたぐ場合は、親画面では子空間の配置物へ、子画面では画面外対象を示す端点へ投影して接続関係を失わない。
- ホース・配管は、物理施工図としては必要でもHubの制御・計測・作業判断に寄与しないため、新規配置の管理対象にしない。旧バージョンで保存済みの `irrigation_line` は後方互換のため表示・移動・削除だけ可能とし、配置パレットには表示しない。
- 空間未選択時は、空間名、空間種別、縦横のマス数、1 マスの実寸を編集する。
- 空間設定では北の向きをスライダーまたは上下左右のプリセットで編集する。方位変更は配置物を回転させず、Canvas に対する実際の北の向きだけを変更する。
- `Delete` で選択配置を削除する。子空間を持つ配置を削除した場合は配下の空間も削除する。
- `Ctrl/Cmd + S` で保存、`Ctrl/Cmd + Z` で Undo、`Ctrl/Cmd + Shift + Z` で Redo する。
- 未保存状態でページを離れる場合はブラウザの離脱確認を出す。
- 圃場詳細や機器詳細から `?space=<space_id>&placement=<placement_id>` 付きで開かれた場合は、指定配置物を含む空間へ移動してその配置物を選択し、右プロパティを直ちに表示する。
- 定植可能な培地を保存後に選択し、作物、品種、作物区分、果樹の場合の樹齢、定植日、株数、培地に合う栽培方式、用土・培地、日当たりを登録する。用土・培地と日当たりは選択式とし、圃場地域は重複入力せず圃場の所在地から取得する。
- AI計画生成ボタンは必須項目と配置保存がすべて満たされた場合だけ有効化する。無効時は不足項目をボタン直前に列挙し、サーバもLLM呼び出し前に同じ条件を検証する。
- 定植フォームの編集中値は配置 ID 単位でブラウザに下書き保存する。別の配置を選んでもその配置の下書きだけを復元し、作物区分や栽培方式を切り替えても共通入力を失わない。
- 定植済み配置を選択すると、作物名、定植日、株数、カレンダー導線を表示する。
- 栽培カレンダーで提案の理由を確認し、編集または実施日を選択して作業を記録する。
- 定植済み配置では、土壌水分、EC、pH、湿度、PAR の目標を有効化し、2 点スライダーで下限と上限を編集する。

植物管理のデータモデルと LLM 利用方針は [HUB_PLANT_MANAGEMENT_CALENDAR_SPEC.md](HUB_PLANT_MANAGEMENT_CALENDAR_SPEC.md) を参照する。

## 5. 空間モデル

空間種別は次のとおり。

- `field`: 圃場全体。ルート空間で使用する。
- `open_field`: 露地栽培エリア。
- `greenhouse`: ハウス内部。
- `indoor`: 建物内。
- `hydroponic`: 水耕設備内。
- `shade`: 軒先など、ハウスではないが日陰となる空間。

1 つの圃場レイアウトは `spaces` 配列を持ち、配置物の `child_space_id` で親子関係を表す。座標、幅、高さはピクセルではなく整数マスで保存する。

各空間は `north_angle_deg` を持つ。値は画面上方向を基準とした時計回りの角度で、範囲は `0..359` とする。`0` は画面上、`90` は画面右、`180` は画面下、`270` は画面左を北として扱う。ハウスなどの子空間は親と異なる図面向きで作成できるため、方位を空間ごとに保持する。子空間の新規作成時は親空間の値を初期値として継承し、その後は独立して編集する。

現行スキーマは version 3 とする。version 2 より前の保存データなど `north_angle_deg` が存在しない空間は `0` として正規化する。この後方互換処理により、既存レイアウトの手動移行は不要とする。

圃場詳細ではこのデータを次の包含ツリーとして投影する。

`圃場 → 空間（ハウス、露地、水耕設備）→ 培地・栽培設備（畝、鉢、植木等）/設備 → デバイス機能`

`child_space_id` と配置先空間は物理的な包含関係である。一方、`binding.target_placement_ids` は潅水・計測対象を表す関連であり、ツリーの親子にはしない。1台のWRSが複数の畝を対象にしてもデバイス配置を複製せず、対象名を関連として表示する。

## 6. デバイス紐づけ

- デバイスは `潅水デバイス`、`環境センサー`、`土壌センサー`、`日射・PAR センサー`、`カメラ`、`その他`の種別グループで選択する。
- 候補には未割当デバイスと、編集中圃場へ割当済みのデバイスだけを返す。ほかの圃場へ割当済みのデバイスは返さない。
- 1 デバイスは 1 レイアウト内の 1 配置物だけに割り当てる。MOSFET SW はデバイス配置の `resource_id` で選択する。
- 潅水デバイスは `target_placement_ids` で潅水する鉢、畝、水耕ベッド、植木を複数選択できる。Canvas では対象へ方向付き接続線を描画し、対象側にも潅水元バッジを表示する。
- 培地にどの潅水デバイスからも到達する関連がない場合は `手動潅水` と解釈する。既定値のため専用デバイスや空の関連レコードは作成しない。
- センサーは必要に応じて計測対象を `target_placement_ids` へ設定する。土壌センサーは培地、環境・日射センサーは培地または空間との対応を明示する。関連は空間をまたいでも保持する。
- 環境センサーの環境区分は設置空間から導出する。ルート圃場に置かれた場合は屋外、ハウス子空間に置かれた場合はハウス内として扱う。
- 対象配置を削除した場合は、全デバイスの `target_placement_ids` から対象 ID を同時に削除する。
- 通常画面は圃場IDを先に確定してからデバイスを取得する。TOPでデバイス候補APIを呼び出してはならない。
- 大量デバイス環境では未割当候補を全件返さず、device IDまたは導入コードによる検索・ページングへ移行する。これは将来のデバイス検索・割当APIで実装する。

## 7. API

| Method | URL | 用途 |
|---|---|---|
| GET | `/local/api/fields/<field_id>/layout` | レイアウト取得。未保存時は既定レイアウトを返す |
| PUT | `/local/api/fields/<field_id>/layout` | レイアウト全体を保存 |
| GET | `/local/api/fields/<field_id>/layout/devices` | 紐付け候補デバイスと MOSFET SW を取得 |
| GET | `/local/api/fields/<field_id>/plantings` | 定植、カレンダー、生成タスク、サジェスト、作業記録を取得 |
| POST | `/local/api/fields/<field_id>/plantings` | 保存済み配置へ定植し、カレンダー生成タスクを登録して HTTP 202 を返す |

PUT は `revision` による楽観ロックを行う。保存済み revision と送信 revision が異なる場合は HTTP 409 を返す。

現行の永続化先は Hub の work directory にある `.field_layouts.json` とする。圃場の生育条件を保存する `.fields.json` とは分離する。多圃場・多拠点運用へ移行する際のDB境界と索引は [HUB_FIELD_RESOURCE_HIERARCHY_SPEC.md](HUB_FIELD_RESOURCE_HIERARCHY_SPEC.md) に従う。

## 9. 現行範囲

初版では次を対象外とする。

- 配置物同士の衝突禁止。
- 回転操作。
- 複数選択、グループ化、コピー貼り付け。
- GPS、航空写真、地図座標との連携。
- ユーザー定義プリセット。
- 複数ユーザーのリアルタイム共同編集。

重なりは、ハウス内に設備を重ねて表現する用途があるため、初版では許可する。

## 10. グラフィック拡張方針

現行の Konva.js Canvas で、プリセット別の図形、画像アイコン、塗りパターン、接続線、選択・警告状態、ズームに応じた詳細度変更を実装できる。Flutter Embedded への置換は不要である。見た目を強化する場合も、座標・関連・操作は現行モデルを維持し、表示部品だけを差し替える。

画像素材を追加する場合は、作物や設備を判別できる透過 PNG/WebP または既存アイコンを使い、当たり判定と選択枠は Konva の配置物ノードで管理する。装飾画像へ業務データを埋め込まない。

## 11. 検証

`hub/admin-ui/scripts/smoke.mjs` は実ブラウザで次を確認する。

1. 北の向きを変更し、Canvas の方位マークと保存データへ反映されることを確認する。
2. ハウスを D&D で追加し、親空間の北向きが子空間へ継承されることを確認する。
3. ハウス名と幅を編集する。
4. ハウス内部へ移動し、畝を 3 本追加する。
5. 圃場へ戻り、潅水機を追加し、`潅水デバイス` グループから WTR/WRS を紐付ける。
6. 潅水対象の鉢または畝を選択し、Canvas に接続線が表示されることを確認する。
7. 植木鉢を追加、保存し、ブルーベリーを定植する。
8. 定植の目標レンジをスライダーで変更して保存する。
9. カレンダー生成、作業記録、質問回答を画面から実行する。
10. API から階層、方位、配置、デバイス紐付け、定植、目標、カレンダー、作業記録を再取得する。
11. デスクトップ、モバイル、カレンダードロワーのスクリーンショットを取得する。

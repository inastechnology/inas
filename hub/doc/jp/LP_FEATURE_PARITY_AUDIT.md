# LP 宣伝内容と Hub 実装の整合性監査

監査日: 2026-07-22  
対象: 公開 LP `lp/index.html` と Hub の UI・API・永続化・デバイス連携

## 判定基準

- **実装済み**: 利用者が Hub から到達でき、API とデータ保存を含む主要経路が存在する。
- **一部実装**: 基盤はあるが、LP の文言をそのまま満たすには不足がある。
- **将来機能**: 安全性または製品設計上、現時点で実装済みと扱うべきでない。

## 今回完了した実装

1. `air_temperature_c` と `soil_temperature_c` を作付け目標、AI 応答、圃場ステータス、管理 UI に通した。
2. 直近の作業記録と植物相談を、件数・文字数を制限した安全なスナップショットとして年間計画生成へ渡した。
3. 計画詳細に、施肥・作業・相談・根拠など「何を反映した計画か」を表示した。
4. 作業完了時に、クライアント入力ではなく認証済みユーザーを実施者として保存・表示した。
5. 作業へ任意の担当者を割り当て、作業者の記録を `確認待ち` として提出できるようにした。
6. 管理者が証跡を承認または差戻しできるようにし、承認済みだけを公式の圃場履歴と AI の次回計画へ接続した。
7. 既存の完了記録は移行なしで承認済みとして扱い、差戻した証跡も監査用に保持した。
8. 管理者向けにメンバー別の完遂・確認待ちと作業絞り込み、作業者向けに本人だけの達成称号と次の節目を追加した。順位、速度、報酬額は表示しない。

検証は Hub 全体 387 件の Python テスト、Ruff、TypeScript/Vite build、管理者／作業者とデスクトップ／モバイルを含むブラウザ smoke を通過した。ブラウザ smoke では、承認済みと確認待ちを別メンバーで集計し、作業者画面に他メンバーの達成カードが出ないことも確認した。

## 採用した製品境界

### 欠測専用アラートは追加しない

センサーの有無と最新値は配置画面・圃場画面から確認できる。設置していないセンサーを異常として扱うと、機器を任意追加できる製品方針と衝突するため、欠測専用アラートは要件にしない。表示される値には取得時刻を添え、利用者が鮮度を判断できる現在の設計を維持する。

### 即時灌水は追加しない

WTR/WRS は省電力を優先し、常時接続や即時応答を製品要件にしない。利用者は Hub で潅水条件・時刻を設定し、端末は次の起床タイミングで Runtime Config を取得して予定を実行する。Hub の設定配信を「今すぐ潅水」と表示しない。

## 優先して残す課題

### P1: 圃場単位のチーム管理

- 圃場単位のメンバー所属と閲覧・編集権限
- メールの直接入力に代わる担当者名簿と招待
- 管理者不在時の代理確認、引継ぎ、期限通知
- 期間・作業種別・差戻しを含む長期集計 API

### P2: 報酬台帳と送金連携

今回の作業確認データは、将来の報酬計算に必要な「誰が・何を・いつ提出し、誰がいつ承認したか」を保持する。ただし、タスクの `completed` と送金を直接結びつけない。次の段階では、作業開始前に合意した単価・通貨・計算方式のスナップショットを持つ報酬台帳を追加し、管理者承認で `earned` を記帳する。給与計算・銀行振込・決済事業者との連携は、法務・労務・取消処理を含む別境界として設計する。詳細は [圃場作業の確認と将来の報酬連携](WORK_VERIFICATION_AND_COMPENSATION_DESIGN.md) を参照。

## リリース判断

LP の主要な「見る・計画する・担当する・提出する・確認する・達成を振り返る・予定を設定する」は Hub に実装されている。省電力端末への即時灌水と欠測専用アラートは不足ではなく、採用しない製品境界として LP にも反映した。圃場単位の細かな権限と報酬・送金は将来機能であり、現時点の LP やデモで実装済みとは扱わない。

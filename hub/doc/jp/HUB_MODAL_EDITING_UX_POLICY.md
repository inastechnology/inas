# Hub 編集・追加画面の表示方針

## 目的

ボタンを押した後に離れた位置へフォームが展開され、利用者が変化を探す状態をなくす。閲覧と編集を分離し、作業中の文脈と未保存入力を守る。

## 原則

1. 追加、編集、再生成条件、校正、実績入力、削除前の重要確認はモーダルで開く。
2. モーダルを閉じたら、開くために押したボタンへフォーカスを戻す。
3. モーダルは背景クリックと Escape で閉じられ、Tab 操作をモーダル内に留める。
4. モーダル表示時は背景を暗くし、短い移動アニメーションで新しく開いた面を認識できるようにする。`prefers-reduced-motion` ではアニメーションを止める。
5. 検索、絞り込み、タブ、詳細の開閉、即時反映される軽い切替は画面内に残す。
6. 設置ビューのインスペクターなど、画面自体が専用エディターである場合は常設編集面を使用する。
7. やむを得ず画面内へ入力欄を展開する場合は、展開先を押下位置の近くに置く。離れる場合は展開先へスクロールし、フォーカスと強調アニメーションを与える。
8. 編集途中に別の管理画面を参照するリンクは新しいタブで開き、入力を失わせない。

## 共通実装

React 管理UIでは `ModalDialog` を使用する。個別画面で背景、フォーカス、Escape、アニメーションを再実装しない。

対象となる主な導線:

- AI栽培計画の作成・作り直し
- 施肥履歴の追加
- 管理作業の追加・編集
- 作業実績と見送り判断の記録
- 圃場と栽培記録の追加
- デバイスの校正や接続設備の編集

## 画面監査

| 画面・操作 | 表示方法 |
| --- | --- |
| AI栽培計画を作り直す | 共通モーダル |
| 施肥履歴を追加 | 共通モーダル |
| 作業を追加 | モーダル |
| 作業内容を編集 | 共通モーダル |
| 作業実績を記録・見送る | 共通モーダル |
| 圃場を追加 | ネイティブ dialog |
| 栽培記録の日付・項目を追加 | モーダル |
| 設置ビュー | 専用エディターの常設インスペクター |
| 絞り込み・表示期間・タブ | インライン操作 |

新しい画面を追加するときは、この分類に当てはめてから実装する。

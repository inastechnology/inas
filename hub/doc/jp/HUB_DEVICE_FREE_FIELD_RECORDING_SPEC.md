# デバイス非依存の圃場記録仕様

## 1. 目的

INA Device Hub の圃場管理は、接続デバイスが0台でも記録アプリとして完結しなければならない。利用者は古いPCなどで Hub を動かし、圃場、ハウス、畝、鉢、水耕ベッドなどを登録して、潅水、培地、環境、栽培作業、収穫を記録できる。

デバイスは利用開始の前提条件ではない。デバイスを追加すると、手入力していた計測と作業が自動取得・自動記録・自動提案へ段階的に置き換わる。この順序を製品全体の基本原則とする。

## 2. 基本原則

1. 圃場、設置場所、作物、記録、カレンダーはデバイスIDなしで作成・閲覧・更新できる。
2. 手入力記録とデバイス取得値は、同じ圃場、設置場所、日付の画面で確認できる。
3. デバイスがないことをエラーや未完了状態として扱わない。
4. デバイス由来の値は読み取り専用とし、デバイス名、設置範囲、値、単位、取得時刻、取得元を保持する。
5. 同じ日に複数デバイス、複数項目、同一項目の複数時刻が存在できる。
6. 手入力フォームに全項目を常時表示しない。利用者が必要な項目だけを検索して追加する。
7. メモ、評価、画像は補助情報として段階的に開示する。

## 3. 記録タブの構成

記録タブは次の順で構成する。

| 領域 | 内容 |
| --- | --- |
| 月間カレンダー | 手入力件数、自動取得件数、画像の有無を日付単位で表示 |
| 記録を追加 | 日時、対象、同日の自動取得値、過去に選択、追加済み記録項目を表示 |
| メモ・評価・画像 | 折りたたみ内に表示し、必要な場合だけ入力 |
| 記録一覧 | 保存済みの手入力、作業、観察を時系列で表示 |

概要タブにセンサー値がない場合は、空のセンサーパネルを主表示にしない。代わりに今日の手入力件数、自動取得件数、`今日を記録` を表示する。時系列グラフと空間別センサー詳細は `環境・設備` タブに置き、取得値がある場合だけ表示する。

## 4. 記録項目の追加

`記録項目を追加` は検索ダイアログを開く。ダイアログは文字検索と、潅水、土壌・培地、環境、栽培作業、収穫の簡易フィルタを持つ。

初期カタログは次を含む。

- 潅水時間、潅水量
- 土壌水分、EC、pH、地温・培地温
- 気温、湿度、PAR
- 施肥量、病害虫・防除、作物の状態
- 収穫量

選択した項目はフォーム最下部へ追加し、項目ごとの削除ボタンで入力前に除去できる。数値範囲、単位、入力形式はサーバ側カタログを正とし、ブラウザから送られたラベルや単位を信用しない。

## 5. 過去に選択

保存済み圃場イベントの `record_values` から最近選択された項目を重複なしで抽出し、最大8件を `過去に選択` として表示する。ブラウザでは項目をフォームへ追加した時点でもローカル履歴へ反映し、入力途中で削除した場合にも再追加しやすくする。

サーバ履歴を正とし、ブラウザストレージが無効でも保存後の再利用性を維持する。

## 6. 記録対象

手入力記録は次のいずれかへ紐づく。

- 圃場全体
- 露地エリア
- 畝
- 植木
- 鉢
- 水耕ベッド

対象IDは設置ビューの placement IDを使用する。保存時に対象が現在の圃場レイアウトに存在することを検証し、表示名をイベントへスナップショットする。これにより、鉢Aの潅水時間や水耕ベッドのECなどを区別できる。

## 7. 自動取得値

圃場へ紐づくデバイスの `sensor_measurements` を表示月の範囲で取得し、ローカル日付へ変換してカレンダーへ統合する。WTR/WRSのステータスに潅水実行時間がある場合は、潅水時間として同じ自動取得領域へ表示する。

日次画面では次の階層で表示する。

1. デバイス名
2. 設置範囲
3. 測定項目
4. 値、単位、取得時刻

同じデバイス・同じ測定項目は1日最大24件を表示対象とし、表示月全体の取得上限を設ける。大量データで月間画面や日次ダイアログの寸法を変化させない。

## 8. 保存モデル

圃場イベントへ次の属性を追加する。

| 属性 | 内容 |
| --- | --- |
| `target_placement_id` | 記録対象の placement ID。圃場全体は空文字 |
| `target_name` | 保存時点の対象表示名 |
| `record_values` | 複数の構造化された手入力値 |

`record_values` の各要素は `key`、`label`、`category`、`value`、`unit`、`input_type` を持つ。`label`、`category`、`unit`、`input_type` はサーバ側カタログから補完する。

既存の `event_type`、`title`、`description`、`rating`、`attachments` は維持する。画像は既存の非公開R2保存を使用する。

## 9. 段階的な自動化

| 状態 | 利用者体験 |
| --- | --- |
| デバイス0台 | 設置場所を選び、必要な項目だけ手入力する |
| センサーあり | 同日の計測値と時刻が自動表示され、手入力は不足分だけ行う |
| 潅水デバイスあり | 潅水実行時間と対象が自動記録される |
| センサーと制御あり | 判断候補、実行、実行中確認、結果記録を連携する |

手入力データと自動データは競合させない。手入力は利用者が観察・実施した事実、自動データは機器が計測・実行した事実として併記する。

## 10. 受入条件

1. デバイス0台の新規圃場で記録タブを開ける。
2. ECを検索して追加し、入力前に削除できる。
3. 削除後も `過去に選択` からECを再追加できる。
4. 同じ記録へ潅水時間とECを入力できる。
5. 鉢や畝を対象として保存できる。
6. 保存後、月間カレンダーと日次ダイアログで値、単位、対象、時刻を確認できる。
7. 同日に複数デバイスと複数時刻の値がある場合、すべてを識別して確認できる。
8. デバイス0台の概要画面に空のセンサー詳細を表示しない。
9. デスクトップとモバイルで検索ダイアログと日次ダイアログが画面内に収まる。

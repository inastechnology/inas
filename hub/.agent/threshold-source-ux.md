# FGT の土壌水分の判定元を選択し、読取エラー時は潅水する

## 目的と受け入れ条件

FGT の動作設定で、個別の土壌水分計または有効な全台の平均を選べるようにする。
選択した対象の名前・場所・最後に届いた値・受信日時を設定の横に表示する。
最後に届いた値、編集中のしきい値、前回の予約で実際に使った測定値を区別する。
選択した値を読めない場合は、ユーザーの指定どおり水分条件では予約を見送らない。

## 実装方針と判断

- Device Definition に汎用の `ui.threshold_rules` と送信時の `capability_requirements` を追加し、FGT 固有のパスと説明を定義側に置く。
- Hub は宣言に沿って対象を解決し、選択入力・測定の出典・比較の目安を一つのパネルへまとめる。測定一覧にも選択対象の目印を表示する。
- Firmware 0.4.0 は従来の自動選択、個別指定、有効な全台の平均に対応する。個別指定は通信速度とアドレスで識別し、一覧の並べ替えで対象が変わらないようにする。
- 平均の対象は有効な土壌水分計すべて。対象のどれかが欠損・非数・範囲外なら平均は未取得とする。個別指定の欠損でも他のセンサーへ代替しない。
- 未取得時は予約の通常運転へ進む。水分値を取得できてしきい値以上のときに、その回の全工程を見送る。履歴・ポンプなど既存の保護は独立して働く。
- 保存形式 V2/V3 を V4 へ読み替えて既存の設定と予約を保持する。旧Firmwareは設定を無視したり読取エラー時に見送ったりするため、対応状態を受信するまで有効な水分設定を送信しない。
- Hub の比較は最後に届いた測定値に基づく目安とする。実際は予約開始直前に再計測する。機器の設定確認と反映待ちを区別する。
- 任意の一部の台だけの平均、他機器の測定値、天気予報による判断は今回の対象に含めない。

## 検証の範囲と残件

実機のポンプ運転とセンサー抜線の確認は未実施。検証手順は FGT の `docs/verification_plan.md` に追記した。
Hub の全体 `ruff format --check` は既存の無関係な4ファイルで未整形を報告するため、そのファイルは変更していない。
`MYPYPATH=src uv run --with mypy python -m mypy --explicit-package-bases src` は依存ライブラリの型情報不足など、48ファイル280件の型エラーで未通過。追加した resolver と変更した設定処理のエラーはない。
ビルド成果物はローカルに作成し、稼働 Hub への反映や実機更新は行わない。

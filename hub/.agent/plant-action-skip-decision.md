# 栽培作業の「確認して見送る」記録を追加する

このExecPlanは作業中に更新する。`hub/AGENTS.md` と `docs/ARCHITECTURE_LAYERING_POLICY.md` に従う。

## 目的

自動生成された期限切れ・不要な栽培作業を、完了や削除と混同せず「現地確認の結果、作業不要と判断した」記録として残せるようにする。判断理由、観察内容、写真、次回確認日を保存し、圃場履歴とAIによる今後の栽培計画改善に利用できるようにする。

## 進捗

- [x] 既存の作業状態、API、UI、AI再生成時のフィードバック利用箇所を調査した。
- [x] リポジトリとサービスに見送り判断の保存・履歴化を実装した。
- [x] 専用APIと型・クライアントを実装した。
- [x] カレンダーUIに見送りフォームと判断記録表示を実装した。
- [x] バックエンド、フロントエンド、統合テストを追加・実行した。
- [x] mainへコミット・pushし、本サーバへ安全に反映して稼働確認した。

## 設計判断

- `completed` は実作業済み、`skipped` は確認の結果不要と判断、削除は入力ミスだけに使う。
- 見送りは汎用PATCHではなく専用POST APIにする。判断情報と写真、圃場履歴、AI改善用フィードバックを一度に記録するため。
- 現在の判断はアクションの `skip_decision` に保持し、監査履歴は圃場イベントとフィードバックにも残す。
- 見送りから予定へ戻した場合、現在値の `skip_decision` は消すが、過去の圃場イベントとフィードバックは残す。
- 見送りによる後続作業の自動生成は行わない。AI再生成時には既存の guidance feedback 経路を利用する。

## 実装方針

1. `PlantManagementRepository` に入力検証と原子的な状態更新を行う `skip_action` を追加し、正規化と再開時の判断情報クリアを実装する。
2. アップロード、作業更新、圃場イベント作成を束ねるアプリケーションサービスを追加し、Flaskルートは入力変換とHTTP応答に限定する。
3. TypeScript型とAPIクライアントを追加し、作業カードに「確認して見送る」フォーム、判断記録、写真、次回確認日を表示する。
4. リポジトリ単体、API統合、UI smoke/build/lint/testを検証する。
5. git差分とランタイムファイル非変更を確認し、mainへpush後、デプロイスキルの手順で本サーバへ反映する。

## 受入条件

- 予定中・進行中の作業を、確認日・理由・観察内容付きで見送りにできる。
- 写真、補足、次回確認日は任意で保存・表示できる。
- 見送り作業は未完了・期限切れ一覧から外れ、完了とは区別して表示される。
- 圃場履歴とAI改善用フィードバックに判断が残る。
- 見送りを予定へ戻せ、過去の監査記録は失われない。
- 既存テストと追加テストが通り、mainと本サーバの稼働実装が一致する。

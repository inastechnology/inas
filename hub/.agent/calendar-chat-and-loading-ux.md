# 年間栽培カレンダーの情報設計、栽培チャット、処理中表示を改善する

このExecPlanは進行中の実装記録である。利用頻度の高い作業確認を先に置き、AI処理中の誤操作を防ぎ、栽培相談を計画と同じ画面で継続できるようにする。実装判断、互換性、試験、画面キャプチャの目視結果を随時追記する。

## 目的

年間栽培カレンダーでは、利用者が最初に知りたい「期限超過・今やる・まもなく」の作業より、作物固有の資料や施肥情報が近くに混在している。AI計画の再作成中は編集ロックの説明はあるが、利用者が押そうとしているカンバン自体から次の行動へ進めない。また、作物への質問は単発の入力と回答だけで、過去の相談を探したり、計画を見ながら継続して相談できない。

処理中表示も画面上部だけではなく、押したボタンそのものに統一して示す。屋外、小型スマートフォン、高齢者の利用を含め、操作の結果と次の行動を視線移動なしで理解できる状態を目標にする。

## 実装タスク

1. 非同期操作を起動するボタンを監査し、処理中は同じボタンへ `aria-busy=true`、進捗図形、処理内容を表す文言を表示する。共通CSSを利用し、動きを減らす設定でも静止した処理中記号を残す。
2. 「栽培基準」をボタンから開くモーダルへ変更し、管理する作物の直下へ置く。出典、要約、潅水、施肥、規則を読みやすい一画面にまとめる。
3. 年間栽培カレンダーを、圃場の作業カンバン、計画の見通し、作物固有のAI計画・栽培基準、施肥の順に整理する。施肥は作物別画面の下部へ移す。
4. AI計画作成中はカンバンに半透明の操作防止レイヤーを重ね、「AI栽培計画を完了してください」から作物別のAI計画状況へ移動できるようにする。
5. 質問UIを会話履歴つきチャットにする。PCは計画の右側へ追従表示し、狭い画面では本文の下へ一列で表示する。質問と回答の履歴を日時つきで表示し、作物を切り替えたときに再取得し、あいまい検索できるようにする。
6. 質問APIに栽培・圃場運用の範囲判定を追加する。農業外、プロンプトや秘密情報の取得、危険行為の依頼はAI呼び出し前に拒否し、DBへ保存しない。回答プロンプトにも同じ境界を明記する。
7. INAS AppのLP・印刷用パンフレットへ、公的・信頼できるWeb資料をAIがすぐ使える栽培基準にまとめ、出典付きで計画へ活用できる機能を掲載する。
8. Python回帰、TypeScript型、管理UIビルド、ブラウザ試験を実行し、PCと390pxスマートフォンの画面を撮影して目視確認する。

## 互換性とデータ設計

質問履歴は既存の `questions` 配列へすでに保存されているためDBスキーマを変更しない。repositoryへ作物別の一覧・検索を追加し、既存レコードをそのまま返す。検索はUnicode正規化後の質問・回答へ複数語の部分一致を適用し、古い履歴も利用できるようにする。

拒否された質問は回答レコードを作らず、HTTP 422と機械判定用コード、利用者向けの次の質問例を返す。単なるAIの拒否文を正常な栽培履歴として保存しない。既存の質問POSTレスポンスは成功時の形式を維持する。

カレンダーと施肥データの保存形式は変更しない。画面順、モーダル、ロックレイヤーは表示上の変更だけであり、既存のカレンダー、生成タスク、肥料履歴をそのまま利用する。

## 安全境界

栽培チャットが扱うのは、登録作物、栽培環境、天候、土壌・培地、水、肥料、病害虫、剪定、収穫、農作業の安全、圃場で使うセンサー・潅水設備である。一般雑談、個人情報、APIキー、内部プロンプト、サイバー攻撃、違法・危険行為は対象外とする。

農薬・肥料・病害診断では、登録作物への適用、製品ラベル、地域指針、実測・専門家確認を促す既存方針を維持する。範囲判定はサーバ側でAI呼び出し前に行い、画面側だけに依存しない。

## 検証と完了条件

- 処理開始直後、押したボタン内に進捗図形と処理中の文言が表示され、二重送信できない。
- 栽培基準ボタンが管理作物の直下にあり、モーダルで根拠資料と管理基準を読める。
- 初期表示で作業カンバンが最優先となり、その直後に年間の見通しがある。施肥は作物別情報の下部にある。
- AI生成中にカンバンの編集操作がレイヤーで防がれ、レイヤー上のボタンから生成状況へ移動できる。
- PCではチャットが右側にあり、計画を見ながら質問できる。390pxでは横溢れせず、履歴、検索、入力、送信が順に使える。
- 保存済み履歴を再読込でき、あいまい検索で質問と回答の両方を絞り込める。
- 農業外または不適切な質問は422となり、AIを呼ばず、履歴件数も増えない。栽培質問は従来通り保存される。
- LPと印刷表示に栽培基準機能が掲載される。
- 全Python回帰、型チェック、ビルド、関連ブラウザ試験、`git diff --check` が成功する。
- PCとスマートフォンの画面キャプチャを実際に開き、情報順、文字、重なり、横溢れ、操作状態を目視確認する。

# 管理作業詳細のジャーナルUXとリッチ編集

このExecPlanは進行中の作業記録である。実装中に分かったこと、判断、検証結果を追記し、単独で変更の意図と完了条件を読み取れる状態を保つ。

## 目的

年間栽培カレンダーの「管理作業の詳細」を、情報が均等に並ぶ設定画面から、利用者が迷わず作業へ移れる作業ノートへ改める。最初に作業期間と「今日やること」が目に入り、その背景と実施判断を `きっかけ → 見きわめ → 今日やること` の流れで理解できることを目標とする。詳細手順や注意事項は必要な人が続けて読める階層へ残す。

作業内容の編集ではHTMLタグを直接入力させない。見出し、太字、色、マーカー、箇条書き、画像追加をツールバーから操作でき、APIへ送る際には既存の `instructions_html` と画像マーカー形式を維持する。

## 分かったこと

- 現在の詳細は `人員 / 見積 / 理由 / 作業` が同じ定義リストに並び、行うべき作業より補助情報が同じ強さで見える。
- `work_plan.start_conditions` と `skip_conditions` が既に構造化されているため、LLM文を再解釈せず判断フローを組める。
- 画像アップロードは `{{image:n}}` をサーバーが保存時に添付画像のfigureへ置換する既存契約を持つ。この契約を変えず、編集面だけ視覚化できる。
- 表示側は許可タグ方式でHTMLをサニタイズしている。色表現は任意styleを許可せず、限定したclassと `mark` のみ追加すれば安全性を保ちやすい。
- デスクトップでは三段フローを横に並べても作業本文が十分な幅を持ち、モバイルでは縦フローの中央に「今日やること」を大きく表示できた。
- contentEditable内の選択範囲はファイル選択画面を開くと失われ得るため、最後の選択Rangeを保持し、写真選択後にその位置へ視覚マーカーを挿入する必要があった。

## 設計判断

- 「理由」は「この作業を考えたきっかけ」、「判断」は「やるか見送るか」、「作業」は「今日やること」と表現する。農作業日誌に近い会話的な語感にし、内部データ名は変更しない。
- 人数と見積時間はタイトル直下の小さなチップへ移し、作業本文とは競合させない。
- 判断条件はフロー内へ集約し、下部の詳しい作業ノートでは対象、確認点、方法、完了目安だけを扱う。
- リッチエディターはブラウザの `contentEditable` と限定コマンドで実装する。新規依存を増やさず、保存値は従来通りHTML文字列と画像マーカーにする。
- 色は任意色コードを保存せず、緑文字、土色文字、黄色マーカーという限定表現だけを許可する。

## 実装手順

`hub/admin-ui/src/plant-calendar/CalendarActionCard.tsx` に判断フローと作業ノートの表示部品を追加する。既存の定義リストを廃止し、タイトル、作業量、フロー、写真付きメモ、詳細ガイドの順へ並べる。編集フォームのラベルも同じ言葉へ合わせる。

同ファイルの `RichActionContentField` をcontentEditableへ変更する。ボタン操作で文書要素を付与し、選択・貼り付け画像は視覚的な挿入位置として見せる。エディターDOMと保存HTMLの相互変換を設け、画像削除時には後続マーカー番号も詰め直す。表示サニタイズには限定classとmarkを追加する。

`hub/admin-ui/src/styles.css` に紙、罫線、付箋、ステップ接続線を模したスタイルを追加する。狭い画面では三段の縦フローにし、ボタンと本文が横にはみ出さないようにする。

ブラウザ試験でフローの順序、編集欄が生HTML textareaではないこと、装飾ボタンが実際にDOMへ反映されることを確認する。最後に本番ビルドを作り、デモサーバーからデスクトップとモバイルの画面を撮影して目視する。

## 検証と完了条件

管理作業の詳細を開いた直後に「今日やること」が最大の本文として認識できる。きっかけ、やる目安、見送る目安が順序立てて見え、同じ開始・見送り条件が下部に重複しない。詳細ガイドは折りたたみを含め利用可能なままである。

編集モーダルにHTMLタグ入力の説明や生HTMLのtextareaがなく、見出し、太字、色、マーカー、リスト、画像の操作がある。保存リクエストは既存の `instructions_html` と画像配列を使用し、既存データも表示・再編集できる。

実行する検証は次の通り。

    cd hub/admin-ui && npm run build
    cd hub && UV_CACHE_DIR=.uv-cache uv run python -m unittest discover -s tests

さらにデモサーバー上でブラウザ回帰を実行し、デスクトップとモバイルのスクリーンショットを取得して、視線順、折返し、モーダル操作を目視する。

## 回復性

UI変更のみで永続データの移行は不要である。保存形式を維持するため旧HTMLはそのまま再編集できる。contentEditableの装飾に失敗してもプレーンテキスト入力と保存は継続できる。ビルド成果物は既存のViteコマンドで再生成できる。

## 結果

詳細画面は、作業期間とタイトルの次に `この作業を考えたきっかけ → やるか、今日は見送るか → 今日やること` を示す作業ノートになった。三段目は濃い緑、大きな本文、人数と時間を備え、ユーザーが行う作業を画面の主役にしている。下部は判断条件を繰り返さず、「見る場所」「見ておくこと」「やり方」「ここまでできたら完了」に整理した。

編集画面から生HTML入力とタグ説明を除き、太字、見出し、黄色マーカー、緑、土色、箇条書き、番号付き手順、装飾解除を用意した。画像は選択中のカーソル位置へ写真カードとして挿入され、保存時だけ従来の `{{image:n}}` へ戻る。表示サニタイズは限定classとmarkだけを許可する。

`npm run build` は成功した。`PYTHON_DOTENV_DISABLED=1 UV_CACHE_DIR=.uv-cache uv run python -m unittest discover -s tests` は338件すべて成功した。`npm run smoke:field-detail` はフロー順、HTML textareaの不在、8個の書式ツール、マーカー反映、写真の視覚挿入、モバイル横溢れを確認して成功した。目視では `/tmp/ina-calendar-planned-action.png`、`/tmp/ina-calendar-action-journal-mobile.png`、`/tmp/ina-calendar-action-journal-mobile-task.png`、`/tmp/ina-calendar-edit-action-modal.png` を確認し、デスクトップとモバイルの双方で主従と折返しに問題がないことを確認した。

デバイスkindは、F/Wが提供する機能とH/W pin contractを表します。接続する部品だけでkindを変えたり、別kindのpin assignmentを混ぜたりしないでください。

デバイス製作は、Raspberry Pi上でHubとMosquittoが起動し、`<hub名>.local`で到達できるようになってから始めます。まだの場合は[自己調達セットアップの全手順](/start/quickstart/)へ戻ってください。

## 選び方

| 必要な機能 | 選ぶkind |
|---|---|
| アナログ土壌水分 + 潅水1出力 | WTR |
| 潅水2出力 + RS485 | WRS |
| battery駆動のアナログ土壌水分だけ | SOI |
| 12V RS485 sensorだけ | ENV |

<Aside type="caution" title="ピンを流用しない">
WTRの `D4` は潅水出力です。WRS/ENVでは `D4` をRS485 directionに使います。同じXIAO ESP32S3でも、device kindごとに役割が異なります。
</Aside>

## 共通の製作フロー

<figure className="process-map" aria-labelledby="device-build-flow-title">
  <div className="process-map__heading">
    <strong id="device-build-flow-title">1台を安全に完成させる順序</strong>
    <span>Build Flow</span>
  </div>
  <ol className="process-map__steps">
    <li><strong>kindを確定</strong><small>pin contractと部品表を固定する</small></li>
    <li><strong>無通電で配線</strong><small>continuity、short、極性を検査する</small></li>
    <li><strong>F/Wを書込</strong><small>正しいprofileでbuild・uploadする</small></li>
    <li><strong>Hubへ接続</strong><small>Wi-Fi、MQTT、device IDを一致させる</small></li>
    <li><strong>受入・封止</strong><small>機能試験、label、筐体を確認する</small></li>
  </ol>
  <figcaption>実負荷は最後に接続します。前段の検査に失敗した場合は通電せず、配線へ戻ります。</figcaption>
</figure>

1. device kindを確定し、そのページのpin contractを印刷します。
2. 電源を外した状態で結線します。
3. continuityとshortを検査します。
4. 電流制限付き電源で初回通電します。
5. F/Wをbuild・uploadします。
6. setup APから2.4GHz Wi-FiとMQTT `<Hub予約IP>:1883`を登録します。
7. Hubへ登録し、状態とRuntime Configを確認します。
8. device-specificな受入試験を行います。
9. ラベルを貼り、筐体を閉じます。

[安全上の注意](/start/safety/)を完了するまで、pumpやvalveへ実負荷を接続しないでください。
